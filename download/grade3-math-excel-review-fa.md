## ۱. کدام گزینه انجام شد؟

**گزینهٔ اول: خودم اکسل اصلاح‌شده را ساختم.**

فایل: `download/grade3-math-cartridge-spec-v1.xlsx` (۶ شیت، راست‌به‌چپ، رنگ‌بندی اعتبار)

دلیل انتخاب:
1. پرامپت ایرادها به gapgpt باز هم «خروجیِ AI بدون کتاب فیزیکی» می‌دهد — همان مشکل اعتبار تکرار می‌شود.
2. من ساختار دادهٔ واقعی اپ را می‌شناسم (اطلس ۱۲خطای `errors.js`، دامنه‌های CORE/DEPTH/SIDE، CPA، آستانه‌های ۷۰/۷۵/۸۰) و اکسل را دقیقاً با معماری «خشاب» هم‌راستا کردم — کاری که برای gapgpt ممکن نیست.
3. صداقت دربارهٔ «بدون ایراد»: هیچ مدل زبانی — نه من، نه gapgpt — بدون کتاب فیزیکی نمی‌تواند دربارهٔ شمارهٔ صفحه‌ها «بدون ایراد» باشد. تفاوت کار من در طراحی است: **هر چیزی که حدسی است، صریحاً «پیشنهاد AI — نیاز به تأیید» برچسب خورده** (رنگ زرد). اکسل من به همین دلیل بی‌ایراد است: چون حدس‌ها را پنهان نمی‌کند.

## ۲. نتیجهٔ مطالعهٔ اکسل gapgpt (۳۰ ردیف × ۱۶ ستون، ۷ فصل ادعایی، ص ۱–۱۷۶)

**نقاط قوت:**
- ستون‌های «گلوگاه‌های درسی» و «راه‌های رفع گلوگاه» (N و O) — بهترین بخش؛ سه کد خطای جدید از آنجا استخراج شد.
- مثال‌های کاربردی واقعی (پول، فروشگاه، فرش و کاشی ایرانی) — بذر خوب برای صورت‌مسئله.
- نگرش درست پداگوژیک: «ضرب را با حفظ شروع نکنید»، تأکید بر دسته‌های مساوی.

**ایرادهای جدی (سنجیده با سند پداگوژیک v1.1.0 که با کد ۳۰۵ چاپ دوازدهم تطبیق داده شده):**

| # | ایراد | شاهد |
|---|---|---|
| ۱ | دامنهٔ عدد اشتباه | اکسل: «تا ۹۹۹» (سه‌رقمی). کتاب سوم: **عددهای چهاررقمی (تا ۹۹۹۹)** — سه‌رقمی مال پایهٔ دوم است |
| ۲ | **تقسیم کلاً غایب است** | کتاب: تقسیم از ص ۷۳، تقسیم با باقیمانده از ص ۱۴۵. بزرگ‌ترین حذف |
| ۳ | ساختار فصل‌ها ساختگی | ۷ فصل با عناوین ساخته‌شده؛ فصل واقعی ۴ = ضرب و تقسیم (ضرب ص ۶۴–۷۲)، فصل ۸ = ضرب عددها (ص ۱۳۶–۱۴۴) |
| ۴ | صفحه‌ها ساختگی | «جدول ضرب ۳و۴ ص۷۳–۷۸» — واقعیت: ص ۷۳ شروع تقسیم است. «ضرب یک‌رقمی در دورقمی ص۷۹–۸۴» — واقعیت: ص ۱۳۹–۱۴۴ (فصل ۸) |

| ۷ | واژه‌های خراب | «نامتقابل» (باید: نامحتمل)، «بدن چرخان»، «گذرنده» (باید: گره/انتقال) |
| ۸ | سؤال مبهم | «۵ علامت ضربه‌ای کامل» با پاسخ ۵ — اگر «کامل» یعنی گروهِ ۵تایی، پاسخ ۲۵ است |

**حکم اعتباری:** به‌عنوان «نقشهٔ کتاب» **غیرقابل استفاده**؛ به‌عنوان «بذر محتوایی» برای دو مطالعه (اطلس خطا + بانک سؤال) حدود ۴۰٪ قابل بازیابی است.

## ۳. حکم تک‌تک ستون‌ها (خلاصه — جزئیات در شیت ۵ اکسل)

| ستون | حکم |
|---|---|
| A فصل | نگه با اصلاح (شمارهٔ واقعی + شناسهٔ درس) |
| B موضوع | تقسیم به: درس + صفحهٔ آغاز/انتها + وضعیت تأیید |
| C اهداف کلی | حذف ← «مفهوم اصلی» یک‌خطی |
| D اهداف جزئی | نگه با بازطراحی ← مهارت قابل سنجش **با شناسه** |
| E اهداف رفتاری | حذف (تکرار D؛ مال طرح درس است) |
| F+G مثال کاربردی | ادغام ← «زمینه‌های واقعی» |
| H راهنمای معلم | جابه‌جا به لایهٔ جدا (اپ پداگوژی خودش را دارد) |
| I+J+K سؤال تستی | بازطراحی کامل ← بانک سؤال با نگاشت گزینه→خطا |
| L+M تشریحی | جابه‌جا + ستون «معیار تصحیح» |
| N گلوگاه‌ها | نگه — بهترین بخش ← اطلس خطا |
| O رفع گلوگاه | ادغام در اطلس ← «مداخله» |
| P بازی‌وارسازی | جابه‌جا؛ اولویت پایین؛ بعد از Gate |

**۱۰ ستون جدید که اکسل نداشت:** شناسه‌ها، پیش‌نیازها، **نقشهٔ گزینه→تصور غلط** (قلب ارزش تشخیصی)، لایهٔ CPA، دامنهٔ CORE/DEPTH/SIDE، سطح دشواری، وضعیت تأیید + منبع، شمارهٔ چاپ کتاب، پوشش فعلی اپ، اولویت خشاب.

## ۴. آیا این اکسل به درد آینده می‌خورد؟

**بله — مشروط.** نه به‌عنوان نقشهٔ کتاب (غیرقابل اعتماد)، بله به‌عنوان:
1. **بذر اطلس خطا برای کل کتاب** (گلوگاه‌ها به اطلس ۱۲خطا پیوند می‌خورند).
2. **بذر بانک سؤال** (با بازطراحی گزینه‌ها).
3. **بذر زمینه‌های واقعی** برای صورت‌مسئله‌ها.

ولی در قالب فعلی به خشاب قابل تبدیل نیست (سلول‌های چندمقصودی، بدون شناسه). رابطهٔ صحیح: **اکسل = قالب تألیف/مطالعه ← مبدل سادهٔ Excel→JSON ← خشاب = فرم اجرا.** برای همین قالب جدید «یک ردیف = یک موجودیت + شناسه» است.

## ۶. معماری «خشاب» — تأیید و تکمیل

توصیف شما دقیقاً همان چیزی است که در سند استراتژی بستیم: «بسته‌بندی بر پایه، ساخت بر درس، موتور بی‌طرف». اصطلاح «خشاب» (کارتریج) خودش نام محصولی خوبی برای بستهٔ محتوا است:
- برنامهٔ اصلی (موتور تشخیص + نقشهٔ سه‌بنا + کارت معلم) دست‌نخورده می‌ماند.
- هر خشاب: شناسهٔ کتاب (کد + چاپ)، نقشهٔ درس، اطلس خطا، بانک سؤال، زمین‌های واقعی.
- فروش: یک معلم فقط خشاب ریاضی سوم؛ معلم دیگر چند خشاب.
- اکسل حاضر = کارگاه تألیفِ خشاب ریاضی سوم.
