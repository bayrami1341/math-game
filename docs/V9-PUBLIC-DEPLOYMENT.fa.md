مقصد: `class-board-2752e`، متعلق به حساب `bayrami1341@gmail.com`.

وضعیت این تحویل: فایل‌های استقرار و کنترل تنظیمات آماده‌اند؛ API عمومی مستقر نشده است. در ۲۰۲۶/۱۰/۱۶، پس از فعال‌شدن پراکسی محلی توسط مالک، خواندن پروژه با حساب اصلی موفق شد. بررسی فقط‌خواندنی APIهای مدیریت این نتایج را داد:

- پروژهٔ `class-board-2752e` فعال است.
- Cloud Billing مقدار `billingEnabled: false` برگرداند.
- Cloud Run Admin پاسخ داد API استفاده نشده یا غیرفعال است؛ سرویس عمومی موجودی تأیید نشد.
- خواندن تنظیمات Authentication با `404 CONFIGURATION_NOT_FOUND` برگشت؛ تنظیم ورود بازی هنوز تأیید/ایجاد نشده است.

انتخاب و آماده‌سازی میزبان، گام باز باقی‌مانده است. مالک اعلام کرده پرداخت و فعال‌کردن Blaze برای او عملی نیست؛ ادامهٔ کار باید با حفظ Spark و بدون فعال‌سازی سرویس پولی انجام شود. تغییر صورتحساب، ایجاد سرویس پولی یا تغییر تنظیمات ورود در این بررسی انجام نشده‌اند. اطلاعات ورود CLI و توکن‌ها در فایل‌های انتشار قرار نگرفتند.

## مسیر آزمایشی با حفظ Firebase رایگان

گزینهٔ بررسی‌شده، Render Free برای اجرای همین سرور و Firebase Spark برای داده و ورود است. فایل `render.yaml` فقط یک Web Service با `plan: free` تعریف می‌کند؛ دیسک، Postgres یا سرویس پولی نمی‌سازد. تا واردکردن این فایل در حساب میزبان، هیچ استقراری انجام نمی‌شود. Auto-deploy نیز خاموش است. هویت سرویس باید به‌صورت Secret File خصوصی در میزبان تنظیم شود؛ تولید یا انتقال آن هنوز انجام نشده است.

طبق مستندات Render در زمان بررسی، این پلن برای آزمایش و پیش‌نمایش است و پس از ۱۵ دقیقه بی‌کاری می‌خوابد؛ شروع دوباره می‌تواند حدود یک دقیقه طول بکشد. این تأخیر از مهلت هشت‌ثانیه‌ای اتصال اولیهٔ فعلی رابط بیشتر است؛ قبل از انتشار این نشانی به کاربران، انتظار و تلاش دوبارهٔ اتصال اولیه باید تکمیل و آزمایش شود. فایل YAML به‌تنهایی این مشکل را حل نمی‌کند.

Render ممکن است برای تأیید بعضی حساب‌ها کارت بخواهد؛ امکان ثبت‌نام و استفادهٔ همین مالک بدون کارت، از ایران، هنوز تأیید عملی نشده است. اگر حساب او به پرداخت نیاز داشت، این گزینه به‌عنوان راهکار بدون کارت پذیرفته نمی‌شود. فعال‌سازی Blaze شرط لازم همهٔ معماری‌های نسخهٔ ۹ نیست؛ فقط مسیر Cloud Run/Functions در پروژهٔ Firebase به آن وابسته است.

مراجع بررسی: مستندات رسمی Firebase Pricing Plans، Render Deploy for Free، Render Blueprint YAML Reference و پاسخ پشتیبانی Render دربارهٔ تأیید کارت. این تحویل همچنان استقرار عمومی موفق یا مناسب‌بودن Render Free برای عرضهٔ نهایی را اعلام نمی‌کند.

## بستهٔ آماده

- `Dockerfile`: اجرای Node 22 با کاربر بدون دسترسی root و وابستگی‌های تولید؛ فایل‌های `.local`، محیطی و اعتبارنامه‌ها وارد بسته نمی‌شوند.
- `.env.example`: مقادیر عمومی مقصد و نام متغیرهای محرمانهٔ مورد نیاز.
- `server/production-config.js`: جلوگیری از اتصال اتفاقی به پروژهٔ دیگر، رد emulator در تولید و اعتبارسنجی مبدأهای HTTPS.
- پیش از بازشدن پورت تولید، یک خواندن از مسیر خصوصی `v9/system/readiness` انجام می‌شود؛ وجود رکورد لازم نیست. خطای دسترسی باعث توقف شروع سرور می‌شود.
- هویت معلم از claim معتبر، UID مجاز یا ایمیل تأییدشده در فهرست محیط سرور تعیین می‌شود. ورود موفق به Firebase CLI به‌تنهایی حساب معلم بازی ایجاد نمی‌کند.

## مسیر استقرار پیشنهادی

میزبان باید اجرای کانتینر Node، HTTPS، اتصال خروجی به Firebase و نگهداری امن اسرار را پشتیبانی کند. Cloud Run گزینهٔ سازگار با این بسته است؛ قبل از ایجاد منابع باید وضعیت صورتحساب و اجازهٔ مالک دربارهٔ هزینه بررسی شود. در این مرحله هیچ سرویس پولی فعال نشده است.

1. دسترسی شبکه به APIهای Google را برقرار و سپس پروژه و وضعیت صورتحساب را با حساب مالک بررسی کنید.
2. برای سرویس، هویت اجرایی مجزا با دسترسی لازم به RTDB و بررسی هویت Firebase تنظیم کنید. از قرار دادن کلید مدیریتی در مخزن، تصویر کانتینر یا `v9-config.js` خودداری کنید.
3. مقدار تصادفی محرمانه برای `MATH_GAME_ID_SECRET` در مخزن اسرار میزبان بسازید و میان استقرارها ثابت نگه دارید؛ کلید محیط محلی را به تولید منتقل نکنید.
4. متغیرهای `.env.example` را در میزبان تنظیم کنید. مقادیر محیطی به‌صورت خودکار از این فایل خوانده نمی‌شوند. ایمیل معلم فقط پس از `email_verified: true` نقش می‌گیرد.
5. کانتینر را بسازید و مستقر کنید. در صورت استقرار چند نمونه، محدودکنندهٔ نرخ فعلی در حافظهٔ هر نمونه مستقل است؛ برای عرضهٔ اولیه شمار نمونه‌ها محدود و پیش از گسترش، محدودکنندهٔ مشترک اضافه شود.
6. در پروژهٔ انتخاب‌شده، روش ورود ایمیلی معلم و ناشناس کودک و دامنهٔ رابط را بررسی و طبق تصمیم مالک تنظیم کنید. اعتبارنامهٔ CLI جای اعتبارنامهٔ سرویس را نمی‌گیرد.
7. نشانی عمومی `/api/v9/meta` باید `mode: production` برگرداند؛ `/api/dev/accounts` نباید حساب آزمایشی نمایش دهد. درخواست بدون توکن به عملیات خصوصی باید رد شود. شروع موفق سرور فقط دسترسی دیتابیس را تأیید می‌کند؛ این آزمون‌های ورود و مجوز نیز جداگانه لازم‌اند.
8. پس از این بررسی‌ها، `apiBase` در `v9-config.js` به نشانی HTTPS تأییدشده تغییر کند و روی GitHub منتشر شود؛ تا آن زمان خالی می‌ماند.
9. مسیر معلم، دعوت، کودک، پاسخ، پایان و گنجینه را با دو مرورگر مستقل و Firebase واقعی امتحان کنید؛ دادهٔ آزمایشی از سوابق واقعی جدا باشد.

برای بررسی ساخت در محیط دارای Docker:

```bash
docker build -t math-game-v9 .
```

این ساخت در رایانهٔ فعلی اجرا نشده است، زیرا Docker در مسیر اجرایی یافت نشد. اعتبارسنجی منطق تنظیمات و آزمون‌های برنامه مستقل اجرا می‌شوند.

## ادامهٔ کار پس از اتصال

لیدربرد نسخهٔ ۹ پس از اتصال عمومی، با اجازهٔ معلم و بر مبنای مأموریت پایان‌یافته و قواعد همسان تکمیل می‌شود؛ تمرین شخصی وارد رتبه‌بندی کلاس نمی‌شود. سپس پنل معلم برای دعوت، نمایش نتایج و مرور نیازهای تمرینی تکمیل خواهد شد. انتشار این بسته به معنی فعال‌شدن این دو قابلیت نیست.
