# لیدربرد زندهٔ کلاس — نسخهٔ ۸.۱

مسیر استفاده: `join.html` ← ورود نام و کد شش‌رقمی ← `index.html` ← پایان یک سکتور در حالت یادگیری Core ← `leaderboard.html`.

## رفتار برنامه

- کد کلاس با ارقام فارسی، عربی و لاتین پذیرفته و به ارقام لاتین تبدیل می‌شود؛ حروف و نشانه‌ها پذیرفته نمی‌شوند.
- ورود یک شناسهٔ تصادفی پایدار در `demo_player_id` ایجاد می‌کند. مرورگرهای مستقل شناسه‌های مستقل دارند. پاک کردن حافظهٔ مرورگر، این هویت را نیز پاک می‌کند.
- نام ذخیره‌شده در صفحهٔ ورود برای نمایش در لیدربرد اولویت دارد. یک مرورگر با یک شناسه، نمایندهٔ یک بازیکن است.
- تعداد پاسخ‌های درست جلسهٔ سکتور در مسیر `rooms/{roomCode}/scores/{playerId}` ثبت می‌شود. نتیجهٔ سکتور بعدی جای نتیجهٔ قبلی همان بازیکن را می‌گیرد؛ امتیاز سکتورها با هم جمع نمی‌شود.
- نمایش نتایج بر حسب امتیاز نزولی است و با تغییر دیتابیس به‌روز می‌شود. نام‌ها به‌صورت متن نمایش داده می‌شوند.
- تغییر کلاس از لینک «ورود یا تغییر کلاس» انجام می‌شود. لیدربرد به `demo_scores` وابسته نیست و امتیاز تصادفی تولید نمی‌شود.
- پایان سکتور همچنان پروندهٔ آموزشی و کلاس محلی را به‌روز می‌کند. این اتصال مربوط به حالت Core است.
- قطع دریافت یا رد دسترسی، در صفحهٔ نتایج پیام دارد. خطای ارسال در Console ثبت می‌شود. ذخیرهٔ آفلاین و ارسال خودکار پس از بازگشت اینترنت در این نسخه پیاده‌سازی نشده است.

## تنظیمات Firebase

`firebase-config.js` به پروژهٔ `class-board-2752e` در حساب `bayrami1341@gmail.com` اشاره می‌کند. مقصد در ۲۰۲۶/۱۰/۱۶ با درخواست مالک تغییر کرد. داده‌های پروژهٔ قبلی `math-game-live-6b991` حذف یا کپی نشده‌اند؛ لیدربرد مقصد جدید از امتیازهای جدید پر می‌شود. ترتیب بارگذاری در بازی و لیدربرد: SDK برنامه، SDK دیتابیس، تنظیمات پروژه، سپس `live-board.js`.

Realtime Database جدید در `europe-west1` ساخته شده است. فایل `firebase/database.rules.json` خواندن ریشه و مسیر خصوصی `/v9` را برای مشتری رد می‌کند. برای سازگاری نسخهٔ ۸.۱ فقط خواندن امتیازهای یک کلاس شش‌رقمی و ثبت/جایگزینی امتیاز یک شناسهٔ بازیکن مجاز است؛ شکل و اندازهٔ فیلدها کنترل می‌شود. حذف عمومی و فیلدهای اضافه مجاز نیستند. `LiveBoard.clearRoom` برای مشتری رد می‌شود؛ پاک‌سازی آزمایشی با دسترسی مدیریتی انجام می‌گیرد.

این مسیر قدیمی همچنان یک لیدربرد دمو بدون احراز هویت است: کسی که کد کلاس را بداند می‌تواند نتایج را ببیند یا امتیاز جعلی با قالب معتبر ثبت کند. فقط نام مستعار وارد کنید. این مسیر برای پروندهٔ خصوصی کودک یا نمرهٔ رسمی مناسب نیست. نسخهٔ ۹ باید از API احرازشده و محاسبهٔ امتیاز سمت سرور استفاده کند؛ داده‌های آن در `/v9` برای مشتری مستقیم بسته‌اند.

مقصد ابزار Firebase در `.firebaserc` ثبت شده و `firebase.json` فقط همین دیتابیس را هدف می‌گیرد. برای انتشار قواعد از `firebase deploy --only database --project class-board-2752e` استفاده کنید؛ قواعد Firestore پروژه تغییر نمی‌کنند.

## آزمون‌های محلی

از ریشهٔ مخزن اجرا کنید:

```bash
node tests/run-mastery.js
node --test tests/live-board.test.js
```

آزمون دوم کد واقعی ورود، پایان سکتور و نمایش لیدربرد را با حافظه‌های مستقل و دیتابیس شبیه‌سازی‌شده اجرا می‌کند. دو بازیکن، جداسازی کلاس‌ها، جایگزینی نتیجهٔ سکتور، جلوگیری از ارسال تکراری، خطای مجوز و قطع اشتراک صفحه بررسی می‌شوند. این آزمون‌ها به Firebase واقعی داده ارسال نمی‌کنند و جای آزمون شبکه و دستگاه واقعی را نمی‌گیرند.

## آزمون پذیرش پس از انتشار

1. مطمئن شوید شاخه‌ای که GitHub Pages منتشر می‌کند، تغییرات نسخهٔ جدید را دریافت کرده است.
2. در دو دستگاه یا دو پروفایل مستقل مرورگر، با نام‌های متفاوت و کد کلاس یکسان از `join.html` وارد شوید؛ در یکی کد را فارسی وارد کنید.
3. در هر دستگاه حداقل یک سکتور Core را تمام کنید. پیام `✅ امتیاز ارسال شد` باید در Console دیده شود.
4. لیدربرد همان کلاس را در هر دو دستگاه باز کنید؛ هر دو نام و امتیاز واقعی باید دیده شوند.
5. هنگام باز بودن لیدربرد یک دستگاه، روی دستگاه دیگر سکتور دیگری را تمام کنید؛ نتیجه باید بدون بارگذاری دوباره تغییر کند.
6. با کد کلاس متفاوت وارد شوید؛ نتایج کلاس قبلی نباید در آن نمایش داده شوند.
