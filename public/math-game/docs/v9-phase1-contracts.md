# فاز ۱ — قرارداد حداقل نسخهٔ ۹.۰

> وضعیت: **قفل و تأییدشده** — فقط قرارداد و نمونه؛ بدون UI و بدون اتصال تولید
> نسخهٔ قرارداد: `9.0.1-phase1` — ساختار داده: `schemaVersion: 1`
> مرجع تصمیم‌ها: [قفل فاز یک](v9-phase1-locked.md)
> تاریخ شروع: ۲۰۲۶/۱۰/۱۶
> ورودی: فاز ۰ بسته + سند معماری v9
> خروجی این فاز: شناسه‌ها، عملیات API، کد خطا، نمونهٔ JSON

---

## ۱. هدف فاز ۱

تعریف زبان مشترک بین رابط، هسته، و سرور آینده طوری که:

1. مرورگر دیگر «امتیاز نهایی» تعریف نکند
2. هویت و کلاس یک مرجع داشته باشند
3. ارسال تکراری اثر اضافه نسازد
4. پیاده‌سازی بعدی (فاز ۲+) بدون عوض کردن قرارداد ممکن باشد

**خارج از دامنهٔ این فاز:** پیاده‌سازی Cloud Functions، UI معلم کامل، IndexedDB، مهاجرت داده.

## ۲. شناسه‌ها

| شناسه | تولید | ویژگی |
|--------|--------|--------|
| `uid` | سیستم احراز هویت | کاربر واردشده (معلم یا دستگاه) |
| `studentId` | سرور | پروندهٔ آموزشی کودک؛ مستقل از دستگاه |
| `classId` | سرور | کلاس؛ **کد ۶ رقمی شناسهٔ اصلی نیست** |
| `inviteId` / `inviteToken` | سرور | دعوت؛ توکن جدا از classId |
| `sessionId` | سرور | یک نوبت تمرین با قواعد ثابت |
| `eventId` | مشتری (تصادفی) یا سرور | یک پاسخ یکتا؛ کلید اثر یک‌باره |
| `requestId` | مشتری | یکتایی درخواست‌های تغییردهنده |
| `assignmentId` | سرور | تکلیف (۹.۱؛ در حداقل ۹.۰ اختیاری) |

قواعد:

- شناسه‌ها تصادفی و فاقد نام/تلفن‌اند
- کد دعوت کوتاه فقط برای ورود انسانی است، نه کلید داده
- هر رکورد پایدار فیلد `schemaVersion` دارد (شروع از `1`)

## ۴. عملیات حداقل API

همهٔ عملیات تغییردهنده نیاز به هویت معتبر دارند مگر جایی که صریحاً گفته شود.
پاسخ‌ها همیشه شامل `ok: true|false` هستند؛ در خطا: `error.code` و در صورت نیاز `error.message` عمومی.

توکن احراز هویت در بدنهٔ JSON نمونه‌ها نیست؛ در لایهٔ انتقال امن بررسی می‌شود. نقش و مجوز هر عملیات نیز جداگانه در سرور بررسی می‌شوند؛ صرف داشتن حساب Firebase مجوز معلم یا مالک کلاس نمی‌سازد. انتخاب HTTP یا callable در این فاز پیاده‌سازی نشده است.

`requestId` و `eventId` حداقل ۸ نویسه دارند. مقدارهای نمونه شناسهٔ واقعی، توکن قابل استفاده یا اثبات مجوز نیستند.

### ۴.۱ `createClass`

**چه کسی:** معلم احراز‌شده

**ورودی:**

```json
{
  "schemaVersion": 1,
  "requestId": "req_example_001",
  "name": "کلاس سوم الف",
  "policy": {
    "leaderboard": "off",
    "membership": "invite_confirm"
  }
}
```

**خروجی موفق:**

```json
{
  "ok": true,
  "classId": "cls_...",
  "name": "کلاس سوم الف",
  "ownerUid": "uid_...",
  "revision": 1
}
```

**خطاهای رایج:** `UNAUTHENTICATED`, `INVALID_PAYLOAD`, `RATE_LIMITED`

---

### ۴.۲ `issueInvite`

**چه کسی:** معلم مالک کلاس

**ورودی:**

```json
{
  "schemaVersion": 1,
  "requestId": "req_example_001",
  "classId": "cls_...",
  "expiresInSeconds": 86400,
  "maxUses": 40
}
```

**خروجی موفق:**

```json
{
  "ok": true,
  "inviteId": "inv_...",
  "token": "human-or-url-safe-token",
  "classId": "cls_...",
  "expiresAt": "2026-10-17T12:00:00Z",
  "maxUses": 40,
  "uses": 0
}
```

**نکته:** توکن برای حدس‌زدن سخت و برای انقضا/سقف مصرف کنترل می‌شود. کد ۶ رقمی نمایشی در صورت نیاز مشتق است، نه شناسهٔ داده.

**خطاها:** `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_PAYLOAD`, `RATE_LIMITED`

---

### ۴.۳ `redeemInvite`

**چه کسی:** دستگاه دانش‌آموز (حتی حساب ناشناس، پس از سیاست سرور)

**ورودی:**

```json
{
  "schemaVersion": 1,
  "requestId": "req_example_001",
  "token": "human-or-url-safe-token",
  "displayName": "مینا"
}
```

**خروجی موفق (عضویت فوری):**

```json
{
  "ok": true,
  "status": "active",
  "studentId": "stu_...",
  "classId": "cls_...",
  "displayName": "مینا"
}
```

**خروجی موفق (نیاز به تأیید معلم — D3):**

```json
{
  "ok": true,
  "status": "pending",
  "studentId": "stu_...",
  "classId": "cls_...",
  "displayName": "مینا"
}
```

**خطاها:** `INVITE_EXPIRED`, `FORBIDDEN`, `INVALID_PAYLOAD`, `RATE_LIMITED`, `UNAUTHENTICATED`

**ممنوع:** برگرداندن فهرست اعضا یا دادهٔ خصوصی کلاس در این پاسخ.

---

### ۴.۴ `startSession`

**چه کسی:** دانش‌آموز با عضویت فعال (یا معلم در مسیر مجاز)

**ورودی:**

```json
{
  "schemaVersion": 1,
  "requestId": "req_example_001",
  "classId": "cls_...",
  "studentId": "stu_...",
  "goal": {
    "type": "sector",
    "sectorId": 1
  }
}
```

**خروجی موفق:**

```json
{
  "ok": true,
  "sessionId": "ses_...",
  "classId": "cls_...",
  "studentId": "stu_...",
  "status": "ACTIVE",
  "rulesVersion": "rv1",
  "questionSetVersion": "qs1",
  "writerEpoch": 1,
  "questions": [
    { "questionId": "q-01", "f1": 2, "f2": 2 },
    { "questionId": "q-02", "f1": 2, "f2": 3 }
  ],
  "revision": 1
}
```

**قواعد:**

- تعریف سؤال و پاسخ درست فقط از سرور/هستهٔ مشترک می‌آید
- کلاینت حق تعیین `score` یا `mastery` ندارد
- یک نویسندهٔ فعال با `writerEpoch`

**خطاها:** `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_PAYLOAD`, `TEMPORARILY_UNAVAILABLE`

---

### ۴.۵ `submitAttempts`

**چه کسی:** نویسندهٔ فعال همان جلسه

**ورودی:**

```json
{
  "schemaVersion": 1,
  "requestId": "req_example_001",
  "sessionId": "ses_...",
  "writerEpoch": 1,
  "attempts": [
    {
      "eventId": "evt_example_001",
      "questionId": "q-01",
      "answer": 4,
      "responseMs": 3200,
      "clientOccurredAt": "2026-10-16T08:30:00Z"
    }
  ]
}
```

**خروجی موفق:**

```json
{
  "ok": true,
  "sessionId": "ses_...",
  "receipts": [
    {
      "eventId": "evt_example_001",
      "status": "ACKNOWLEDGED",
      "acceptedAt": "2026-10-16T08:30:01Z",
      "correct": true,
      "revision": 2
    }
  ],
  "sessionRevision": 2
}
```

**رفتار تکرار:**

| حالت | نتیجه |
|------|--------|
| همان `eventId` + همان محتوا | همان رسید قبلی؛ اثر اضافه نیست |
| همان `eventId` + محتوای متفاوت | `EVENT_CONFLICT`؛ پاسخ اول حفظ می‌شود |
| `writerEpoch` قدیمی | `STALE_WRITER` |

**کلاینت نمی‌فرستد:** `score`, `mastery`, `acceptedAt`, نقش کاربر.

**خطاها:** `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_PAYLOAD`, `EVENT_CONFLICT`, `STALE_WRITER`, `RATE_LIMITED`, `TEMPORARILY_UNAVAILABLE`

---

### ۴.۶ عملیات تکمیلی حداقل (قرارداد کوتاه)

این‌ها در فاز ۱ فقط امضا می‌شوند؛ پیاده‌سازی می‌تواند فاز ۴ باشد.

| عملیات | نقش | خلاصه |
|--------|-----|--------|
| `finalizeSession` | نویسنده / سیستم | پایان جلسه پس از پاسخ‌های لازم |
| `getSyncStatus` | دانش‌آموز / معلم مجاز | revision و وضعیت پذیرش |
| `grantDeviceAccess` | معلم | اتصال دستگاه دوم به `studentId` |

## ۵. کدهای خطای ثابت

| کد | معنی برای کلاینت |
|----|------------------|
| `UNAUTHENTICATED` | ورود لازم است |
| `FORBIDDEN` | مجوز نیست |
| `INVITE_EXPIRED` | دعوت باطل یا تمام‌شده |
| `INVALID_PAYLOAD` | ورودی نامعتبر |
| `EVENT_CONFLICT` | eventId تکراری با محتوای فرق |
| `STALE_WRITER` | نویسندهٔ جلسه عوض شده |
| `RATE_LIMITED` | زیاد درخواست شده |
| `TEMPORARILY_UNAVAILABLE` | بعداً دوباره تلاش |

پیام نمایشی فارسی در UI است؛ API پیام عمومی و غیرافشاگر برمی‌گرداند.

## ۶. وضعیت‌های دامنه (حداقل)

### جلسه

```text
LOCAL_DRAFT → ACTIVE → FINALIZING → FINALIZED
                   ↘ ABANDONED
```

### عضویت

```text
pending → active → revoked
```

### صف محلی (فاز ۵؛ فقط نام‌گذاری قرارداد)

```text
PENDING → SENDING → ACKNOWLEDGED
            ↘ RETRY_WAIT → PENDING
            ↘ BLOCKED | CONFLICT
```

## ۱۲. نحوهٔ استفاده از اسکما

نسخهٔ اصلاح فایل اسکما `artifactRevision: 1.0.1` است؛ تصمیم‌های D1–D4 و نسخهٔ قرارداد `9.0.1-phase1` حفظ شده‌اند. اصلاح‌ها شامل تکمیل اعتبارسنجی شکل ورودی‌ها، پاسخ‌های مستند و اصلاح نمونه‌های ناسازگار با حداقل طول شناسه است. تغییر آیندهٔ قرارداد باید نسخهٔ صریح داشته باشد.

هر عملیات دو مرجع استاندارد دارد؛ مثلاً `#/$defs/createClassRequest` و `#/$defs/createClassResponse`. خطا با `#/$defs/apiError` بررسی می‌شود. برای کنترل یک عملیات مشخص باید همان مرجع انتخاب شود؛ اعتبارسنجی ریشه فقط تعلق داده به یکی از انواع کاتالوگ را بررسی می‌کند و جای انتخاب عملیات نیست.

فقط فیلدهای مستند پذیرفته می‌شوند. `score`، `mastery`، `acceptedAt` و نقش ارسالی مشتری در هیچ درخواست مجاز نیستند. `startSession.goal` فعلاً فقط شکل مستند `sector` و `sectorId` مثبت را پوشش می‌دهد؛ هدف آموزشی تازه نیاز به قرارداد نسخه‌دار دارد.

`default: "off"` در اسکما توصیف پیش‌فرض قراردادی است. اعتبارسنج داده را تغییر نمی‌دهد؛ سرور آینده باید این پیش‌فرض را اعمال کند. هیچ پیش‌فرض جدیدی برای سیاست عضویت در این فاز تعیین نشده است.

اسکما طول و شکل داده را بررسی می‌کند؛ تصادفی‌بودن توکن، مالکیت، عضویت، سقف مصرف، انقضا نسبت به ساعت سرور، محدودیت نرخ و رفتار تکرار به پیاده‌سازی و آزمون سرور نیاز دارند. طول حداقل توکن در نمونهٔ اولیه تضمین امنیت توکن نیست.
