## تصمیم‌های عملیاتی (موقت تا قبل از تولید)

این مقادیر **قرارداد اجرایی فازهای ۲–۵** هستند. تغییر هرکدام باید با bump صریح نسخهٔ قرارداد ثبت شود.

| کد | موضوع | مقدار قفل‌شده |
|----|--------|----------------|
| **D1** | ورود معلم | `teacherAuth: firebase_email_link` |
| **D2** | سرور مورد اعتماد | `trustedApi: cloud_functions_or_equivalent` |
| **D3** | عضویت دانش‌آموز | `redeemInvite` مجاز است `status: "pending"` یا `"active"` برگرداند (سیاست کلاس: `invite_confirm` یا `invite_open`) |
| **D4** | رتبه‌بندی در ۹.۰ | `leaderboardDefault: off` |

### پیامدهای قراردادی

- **D1:** نقش معلم فقط پس از احراز هویت Firebase معتبر است؛ پین محلی مجوز سرور نیست.
- **D2:** نوشتن نمره / عضویت / نقش فقط از API مورد اعتماد؛ مرورگر مستقیم به دفتر جلسه نمی‌نویسد. اگر Functions ممکن نبود، جایگزین باید **همان قرارداد** را پیاده کند.
- **D3:** کلاینت باید هر دو وضعیت `pending` و `active` را تحمل کند؛ تمرین معتبر کلاس فقط با `active`.
- **D4:** `createClass.policy.leaderboard` پیش‌فرض `"off"`؛ لیدربرد ۸.۱ مسیر دمو/سازگاری است نه نتیجهٔ معتبر ۹.۰.

## محدودهٔ قفل‌شده

### داخل قفل
- شناسه‌ها: `uid`, `studentId`, `classId`, `sessionId`, `eventId`, `requestId`, …

- امضای کوتاه: `finalizeSession`, `getSyncStatus`, `grantDeviceAccess`
- کدهای خطا و رفتار تکرار `eventId`
- مرز اعتماد مرورگر / سرور

### خارج از قفل (عمداً باز برای فاز بعد)
- پیاده‌سازی واقعی Functions / سرور
- UI
- IndexedDB و صف آفلاین
- مهاجرت دادهٔ ۸.۱
- متن دقیق قالب ایمیل ورود معلم
