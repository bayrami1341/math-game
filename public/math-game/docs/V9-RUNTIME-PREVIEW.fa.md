# پیش‌نمایش اجرایی سرور و رابط نسخهٔ ۹

وضعیت: نمونهٔ قابل اجرای محلی؛ آداپتور ذخیره‌سازی با Firebase واقعی آزموده شده، اما API عمومی و ورود واقعی تولید تأیید نشده‌اند. وضعیت به‌روز و کارهای باقی‌مانده در [گزارش ۱۷ اکتبر](V9-REMAINING-WORK.fa.md) آمده است. شمار آزمون‌ها و فهرست شرط‌های انتهای این سند مربوط به تحویل اولیه‌اند.

قرارداد پایه `9.0.1-phase1` و قرارداد `9.0.2-runtime-preview` حفظ شده‌اند. [الحاقیهٔ `9.0.3-entry-preview`](V9-ENTRY-IMPLEMENTATION.fa.md) ثبت نام در داستان، پروندهٔ مستقل از کلاس، تمرین شخصی، مأموریت و گنجینه را اضافه می‌کند. شمارهٔ بازی قبلی همچنان ۸.۱ است؛ عرضهٔ نهایی ۹.۰ اعلام نمی‌شود.

## آنچه پیاده‌سازی شده

- هستهٔ آموزشی مشترک در مرورگر و Node، با حفظ آزمون‌های تسلط قبلی.
- API ایجاد کلاس، صدور دعوت، عضویت، شروع جلسه و ارسال پاسخ مطابق پنج قرارداد فاز یک.
- عملیات تکمیلی شناخت نقش، مشاهدهٔ کلاس، تأیید یا لغو عضویت، وضعیت همگام‌سازی و پایان جلسه.
- محاسبهٔ درستی پاسخ و خلاصهٔ آموزشی در سرور؛ ورودی نمره یا نقش از مرورگر پذیرفته نمی‌شود.
- شناسه‌های شبه‌تصادفی مشتق‌شده در سرور با HMAC و کلید محرمانهٔ پایدار، مستقل از نام کودک.
- ثبت اتمی یک بستهٔ پاسخ، رسید پایدار و جلوگیری از اثر تکراری درخواست و پاسخ.
- رابط فارسی معلم و کودک، با رتبه‌بندی خاموش.
- ذخیرهٔ تراکنشی پاسخ و صف در IndexedDB، دریافت رسید، تکرار با فاصلهٔ افزایشی و نگهداری خطای دائمی برای بررسی.
- ذخیرهٔ فایل محلی برای توسعه و آداپتور تراکنشی Firebase RTDB برای استقرار جداگانه.

## اجرای محلی

Node.js نسخهٔ ۲۲ یا جدیدتر لازم است. در ریشهٔ مخزن:

```bash
npm ci --ignore-scripts
npm test
npm run dev:v9
```

نشانی را در مرورگر باز کنید:

```text
http://127.0.0.1:9090/v9.html
```

سه حساب آزمایشی فقط در حالت محلی وجود دارند: معلم، دانش‌آموز اول و دانش‌آموز دوم. اطلاعات این حساب‌ها واقعی نیست. سرور محلی فقط به loopback متصل است و برای شبکهٔ مدرسه یا اینترنت استفاده نمی‌شود.

داده و کلید توسعه در `.local/v9` ذخیره می‌شوند و وارد Git نمی‌شوند. فایل محلی برای یک فرایند سرور است و جای دیتابیس چندنمونه‌ای تولید را نمی‌گیرد. با راه‌اندازی مجدد، توکن ورود محلی عوض می‌شود؛ انتخاب دوبارهٔ همان حساب آزمایشی به دادهٔ همان uid می‌رسد.

## آزمون دستی مسیر اصلی

1. با حساب معلم کلاس بسازید و دعوت را کپی کنید.
2. با دانش‌آموز اول وارد داستان شوید و نام ساختگی قهرمان را در صحنهٔ معرفی بنویسید. سپس از «کلاس من» فقط دعوت را وارد کنید.
3. اگر سیاست کلاس تأیید معلم است، حساب معلم را باز و عضویت را تأیید کنید.
4. در حساب کودک «بررسی وضعیت کلاس» و سپس «تمرین در همین کلاس» و شروع تمرین را بزنید. برای فعالیت شخصی به دعوت کلاس نیاز نیست.
5. پاسخ‌ها را ثبت کنید؛ پس از رسید سرور، پایان و دریافت نتیجه را بزنید.
6. در حساب معلم، کلاس را تازه‌سازی کنید و نتیجه را ببینید.
7. برای آزمون قطع ارتباط، پس از آغاز تمرین شبکه را قطع و پاسخ ثبت کنید؛ پس از بازگشت ارتباط پاسخ‌های منتظر را ارسال کنید.

خروج از حساب با پاسخ‌های منتظر مجاز نیست. دادهٔ localStorage نسخهٔ ۸.۱ به این پرونده تبدیل نمی‌شود.

## تنظیمات استقرار سرور واقعی

این تحویل هیچ صورتحساب، روش ورود، نقش تولید یا قوانین Firebase زنده را تغییر نمی‌دهد. سرور Node در GitHub Pages اجرا نمی‌شود؛ رابط می‌تواند روی Pages باشد و API روی میزبانی HTTPS جداگانه قرار گیرد.

ورودی‌های محیطی سرور:

| متغیر | کاربرد |
|---|---|
| `FIREBASE_PROJECT_ID` | شناسهٔ صریح پروژه؛ مقصد انتخاب‌شده `class-board-2752e` است |
| `MATH_GAME_ID_SECRET` | کلید تصادفی محرمانهٔ حداقل ۳۲ نویسه؛ در مدیریت اسرار سرور |
| `FIREBASE_DATABASE_URL` | نشانی RTDB مورد استفادهٔ محیط انتخاب‌شده |
| `GOOGLE_APPLICATION_CREDENTIALS` یا هویت مدیریت‌شدهٔ میزبان | اعتبارنامهٔ سرور، خارج از مخزن و پوشهٔ عمومی |
| `MATH_GAME_TEACHER_UIDS` | فهرست UIDهای معلم با جداکنندهٔ ویرگول؛ یا custom claim معتبر `teacher: true` |
| `MATH_GAME_TEACHER_EMAILS` | ایمیل‌های مجاز معلم در سرور؛ فقط با claim معتبر `email_verified: true` پذیرفته می‌شوند |
| `MATH_GAME_ALLOWED_ORIGINS` | مبدأهای مجاز، برای مثال `https://bayrami1341.github.io`؛ بدون مسیر |
| `PORT` | پورت میزبان؛ پیش‌فرض ۹۰۹۰ |

پس از آماده‌سازی محیط:

```bash
npm ci --omit=dev --ignore-scripts
npm run start:v9
```

entry point تولید بدون کلید و تنظیمات لازم اجرا نمی‌شود و متغیرهای اتصال emulator را رد می‌کند. API با Firebase Admin توکن را با بررسی لغو اعتبار بررسی می‌کند. داشتن حساب Firebase به‌تنهایی نقش معلم ایجاد نمی‌کند.

پروژه و نشانی دیتابیس باید با هم تطبیق داشته باشند. سرور پیش از پذیرش ترافیک، دسترسی به مسیر خصوصی دیتابیس را بررسی می‌کند. بسته و مراحل اتصال عمومی در [راهنمای استقرار](V9-PUBLIC-DEPLOYMENT.fa.md) آمده‌اند؛ آماده‌بودن بسته به معنی استقرار زنده نیست.

کلید HMAC باید پشتیبان امن داشته باشد. تغییر بی‌برنامهٔ آن شناسهٔ مشتق از درخواست تکراری را تغییر می‌دهد؛ چرخش کلید نیاز به طرح مهاجرت دارد.

در `v9-config.js` فقط نشانی HTTPS سرور در `apiBase` و تنظیمات عمومی وب Firebase در `firebase` قرار می‌گیرند. کلید مدیریتی و کلید HMAC هرگز در این فایل قرار نمی‌گیرند. ورود ایمیلی معلم و ورود ناشناس دانش‌آموز باید در محیط انتخاب‌شده فعال و دامنهٔ برگشت ایمیل مجاز باشد. تنظیمات حساب و هزینه قبل از فعال‌سازی عمومی بررسی می‌شوند.

## تصمیم‌های اجرایی تکمیل‌شده

| موضوع باز فاز یک | رفتار این پیش‌نمایش |
|---|---|
| خطای یک پاسخ داخل بسته | کل بسته رد می‌شود؛ بدون ثبت جزئی |
| requestId تکراری | دامنهٔ کاربر/عملیات/رکورد؛ همان ورودی همان نتیجه، ورودی متفاوت تعارض |
| eventId تکراری | در همان جلسه؛ ترتیب کلیدهای JSON بی‌اثر است، مقدار همهٔ فیلدهای پاسخ مقایسه می‌شود |
| پاسخ دوباره به یک سؤال با eventId تازه | تعارض؛ برای تمرین دوباره سؤال یا جلسهٔ مستقل لازم است |
| زمان مشتری | اطلاعات کمکی؛ acceptedAt و revision از سرور هستند |
| پایان جلسه | فقط با همهٔ سؤال‌ها؛ تکرار پایان امتیاز تازه نمی‌سازد |
| مدت دعوت | پیش‌فرض یک روز، حداقل ۶۰ ثانیه و حداکثر هفت روز |
| مصرف دعوت | پیش‌فرض ۴۰، حداکثر ۱۰۰؛ pending نیز یک مصرف است |
| بستهٔ پاسخ | حداکثر ۵۰ پاسخ؛ بدنهٔ HTTP حداکثر ۶۴ کیلوبایت |
| زمان پاسخ | عدد صحیح نامنفی، حداکثر یک ساعت؛ اثبات زمان واقعی کودک نیست |
| اندازهٔ شناسه | شناسه‌های مسیر و درخواست، نویسهٔ امن و حداکثر ۱۲۸ نویسه |
| رسیدها | فعلاً در عمر جلسه باقی می‌مانند؛ سیاست پاک‌سازی تولید هنوز تعیین نشده |
| گزارش معلم | محاسبه هنگام درخواست، حداکثر ۲۰ جلسهٔ آخر بر اساس زمان ساخت |

حداکثر ۲۰۰ شناسهٔ درخواست در دفتر هر جلسه و هر عضویت نگهداری می‌شود. پس از آن درخواست تازه با محدودیت نرخ رد می‌شود و رسید قبلی محفوظ است. احراز عضویت پیش از نوشتن انجام می‌شود؛ درخواست در حال اجرا ممکن است هم‌زمان با لغو عضویت تمام شود. لغو، پاسخ‌های قبلاً پذیرفته‌شده را حذف نمی‌کند.

## قرارداد تکمیلی HTTP

همهٔ عملیات `POST /api/v9/{operation}`، بدنهٔ JSON و `Authorization: Bearer ...` دارند. خطا با `{ok:false,error:{code,message}}` و وضعیت HTTP متناسب برمی‌گردد. خطای زیرساخت به پیام عمومی تبدیل می‌شود.

| عملیات تکمیلی | ورودی افزون بر schemaVersion | خروجی اصلی |
|---|---|---|
| getIdentity | ندارد | uid و teacher تعیین‌شدهٔ سرور |
| getClass | classId؛ برای کودک studentId | نمای محدود کودک یا اعضا و خلاصهٔ کلاسِ مالک |
| setMembership | requestId، classId، studentId، status برابر active یا revoked | وضعیت تصمیم ثبت‌شده |
| getSyncStatus | sessionId | وضعیت، receiptها، سؤال‌ها و خلاصهٔ محاسبه‌شده |
| finalizeSession | requestId، sessionId، writerEpoch | وضعیت نهایی، نمره و خلاصهٔ جلسه |

شکل درخواست‌ها در `contracts/v9-runtime-api.schema.json` ثبت شده است. پنج درخواست فاز یک همان مرجع قبلی را دارند. درخواست replay برای startSession همان پاسخ آغاز اولیه را بازمی‌گرداند؛ وضعیت تازه باید با getSyncStatus خوانده شود. issueInvite تکراری نیز پاسخ اولیهٔ صدور را بازمی‌گرداند، نه شمارندهٔ مصرف فعلی.

## پروژهٔ انتخاب‌شده برای تولید

از ۲۰۲۶/۱۰/۱۶ مقصد انتخاب‌شدهٔ مالک، `class-board-2752e` در حساب `bayrami1341@gmail.com` است. تنظیمات عمومی `v9-config.js` و پروژهٔ پیش‌فرض CLI با این مقصد هماهنگ‌اند. Realtime Database در `europe-west1` ایجاد شده و متغیر `FIREBASE_DATABASE_URL` سرور باید برابر `https://class-board-2752e-default-rtdb.europe-west1.firebasedatabase.app` باشد. پروژهٔ قبلی و داده‌های آن باقی‌اند؛ انتقال داده انجام نشده است.

`apiBase` عمداً خالی است، زیرا سرور تولید هنوز مستقر نشده است. تنظیمات Firebase وب به‌تنهایی API را فعال نمی‌کند. پروژه در زمان انتخاب روی Spark بود؛ استقرار Cloud Functions نیاز به فعال‌سازی Blaze و تصمیم مالک دربارهٔ هزینه دارد. ورود معلم، ورود ناشناس، دامنه‌های مجاز، نقش معلم و آزمون سرور تولید همچنان مراحل بعد هستند.

## مرز امنیت پایگاه داده

مرورگر پیش‌نمایش مستقیماً به RTDB نمی‌نویسد و همهٔ دادهٔ خصوصی را از API می‌خواند. آداپتور سرور فقط مسیر `/v9` را مصرف می‌کند؛ دادهٔ rooms نسخهٔ ۸.۱ را نمی‌نویسد.

فایل `firebase/database.rules.json` قواعد کامل دیتابیس مقصد جدید است: ریشه بسته، `/v9` بسته و دسترسی عمومیِ سازگار با دموی ۸.۱ محدود به مسیر امتیاز یک کلاس و ساختار معتبر آن است. `firebase/v9.rules.fragment.json` صرفاً مرجع بخش نسخهٔ ۹ باقی می‌ماند. قواعد پروژهٔ قبلی و Firestore دست‌نخورده‌اند. نمره‌های دمو قابل جعل‌اند؛ اطلاعات خصوصی نسخهٔ ۹ نباید در `rooms` ذخیره شوند. آزمون منفی دسترسی مستقیم لازم است؛ ورود به API به‌تنهایی مسیر مستقیم باز دیتابیس را امن نمی‌کند.

در API محدودیت نرخ در حافظهٔ هر فرایند وجود دارد؛ برای استقرار چندنمونه‌ای و عمومی، کنترل توزیع‌شده و سیاست سوءاستفاده لازم است.

## آنچه هنوز شرط انتشار نهایی است

- استقرار تأییدشدهٔ API و پیکربندی ورود ایمیلی روی دامنهٔ واقعی؛
- آزمون آداپتور با Firebase/emulator و آزمون قوانین مثبت و منفی؛
- آزمون کامل دو دستگاه فیزیکی، مشاهدهٔ بصری دسکتاپ و موبایل؛
- اتصال دستگاه دوم و بازیابی پروندهٔ دانش‌آموز ناشناس؛ خروج از حساب ناشناس فعلاً بازیابی خودکار ندارد؛
- مهاجرت دادهٔ ۸.۱، پشتیبان‌گیری تولید و سیاست نگهداری داده؛
- صفحه‌بندی کامل فهرست اعضا، خلاصهٔ رشد چندجلسه‌ای و تکلیف شخصی؛
- انتقال نویسنده، سناریوهای چندتب و بهبود بازیابی همهٔ فرمان‌های مدیریتی پس از پاسخ گم‌شده؛
- بازشدن آفلاین برنامه از حالت بسته؛ صف پس از بارگذاری کار می‌کند و پوستهٔ آفلاین هنوز کش نمی‌شود.

نتیجهٔ اعتبارسنجی محلی: **۸۸ آزمون موفق** شامل ۳۵ آزمون قبلی، ۳۱ آزمون قرارداد و ۲۲ آزمون سرور و صف. آزمون دو کاربر با سرور محلی و IndexedDB شبیه‌سازی‌شده انجام شده است. این آزمون‌ها به معنی تأیید Firebase واقعی یا مشاهدهٔ بصری نیستند. اتصال ابزار Chrome در این نوبت برقرار نشد. این نسخه برای دادهٔ واقعی کودکان تا عبور از دروازه‌های بالا آماده اعلام نمی‌شود.
