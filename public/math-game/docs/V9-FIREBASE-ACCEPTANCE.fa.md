# پذیرش نسخهٔ ۹ با Firebase واقعی

تاریخ: ۱۷ اکتبر ۲۰۲۶. پروژه: `class-board-2752e`. نتیجه: موفق؛ API عمومی هنوز مستقر نیست.

## محیط آزمون

سرور HTTP برنامه روی رایانهٔ توسعه با حالت `production` اجرا شد؛ حساب‌های توسعه غیرفعال بودند. سه حساب ناشناس موقت از سرویس واقعی Firebase Authentication ساخته شدند و Admin SDK توکن‌های واقعی آن‌ها را با بررسی ابطال تأیید کرد. هیچ توکن جعلی یا emulator در این اجرا استفاده نشد.

فقط UID اولین حساب در تنظیمات همان فرایند آزمون به‌عنوان معلم مجاز شد؛ مجوز یا claim دائمی برای حساب‌ها ایجاد نشد. داده‌ها با FirebaseStore در Realtime Database واقعی پروژه نوشته شدند. اعتبار مدیریتی موجود مالک فقط در حافظهٔ فرایند آزمون استفاده شد؛ این اعتبار جای هویت اجرایی مستقل میزبان عمومی را نمی‌گیرد.

## شبکه و پاک‌سازی

در تلاش اولیه، دریافت کلیدهای عمومی Google توسط Admin SDK پاسخ HTML با خطای ۴۰۳ گرفت؛ حساب‌ها و تنظیمات Authentication معتبر بودند. در ابزار آزمون، عامل HTTPS صریح برای پراکسی فعال رایانه تنظیم شد و اعتبارسنجی واقعی موفق شد. اعتبارسنجی امضا، گواهی TLS یا بررسی ابطال غیرفعال نشد. این تنظیم مخصوص محیط آزمون بود و پراکسی محلی وارد تنظیمات میزبان عمومی نشده است.

شش حساب موقت دو تلاش اولیه با شناسه‌های دقیق شناسایی و حذف شدند. در اجرای موفق نیز ۱۳ مسیر دقیق نوشته‌شده و هر سه حساب موقت حذف شدند. مسیر مشترک `v9` یا `rooms` حذف نشد و داده‌های کلاس واقعی ۹۱۸۴۲۶ تغییری نکردند. رمز، توکن، فایل کلید و دادهٔ هویتی آزمون در گزارش یا فایل‌های انتشار قرار نگرفتند.

## حدود تأیید و گام بعد

این اجرا آزمون خودکار API با کاربران مستقل است؛ ورود تعاملی Google، رابط مرورگر، استقرار HTTPS عمومی، هویت اجرایی میزبان و دو دستگاه فیزیکی را تأیید نمی‌کند. نتیجه به شمار ۱۴۵ آزمون محلی قبلی اضافه نشده است.

برای تست همکاران، حساب و سرویس میزبان، هویت اجرایی خصوصی و تنظیم `apiBase` پس از تأیید سرویس لازم‌اند. سپس مالک با Google وارد پنل شود، دعوت را به دستگاه دوم بفرستد و نتیجهٔ مأموریت در تابلو و گزارش کنترل شود. طرح Firebase در این مرحله ارتقا داده نشد و هیچ سرویس هزینه‌داری ایجاد نشد.
