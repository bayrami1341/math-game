# مدیریت خودکار G2؛ مرزِ آزمون مکانیکی و حکم آموزشی

تأیید کلی کاربر به‌منزلهٔ اجازهٔ ادامهٔ **کارهای فنی** و اجرای نقشه است. به‌معنی آن نیست که یک سیستم بدون شاهد صفحه، بازرس مستقل یا حکم معلم، ردیف‌های زرد را سبز کند. شرط «کتاب فیزیکی و شاهد» و ممنوعیت جعل مُهر همچنان معتبرند.

## اکنون چه چیز خودکار شد؟

- اسکریپت محلی `g2_gate.py` **دو بار اجرا و پاس** شد. تنظیمات workflow `g2-cartridge-gate.yml` برای push/PR به شاخه افزوده شده، اما پس از push هنوز در GitHub به‌عنوان workflow ثبت نشده (`gh run list --workflow` پاسخ 404 و `gh pr checks 3` بدون check بود). همچنین PR #3 با مبنای `v10.3-beta` وضعیت `CONFLICTING` دارد؛ `git merge-base HEAD origin/v10.3-beta` نیز کد ۱/بدون نیای مشترک داد، پس این مشکل صرفاً یک تعارضِ چند خطی نیست. بنابراین **CI راه‌اندازی‌شده فرض نشود**؛ تا آشتی شاخه و ثبت/اجرای واقعی check، دستور محلی زیر در هر تغییر باید اجرا شود.
- این workflow وقتی در GitHub فعال و قابل اجرا شد، با هر push/PR مبنای رسمی را می‌گیرد. اگر SHA رسمی تغییر کرده باشد **قرمز و توقف**؛ کار قبلی بی‌صدا بر رسمی تازه overwrite نمی‌شود.
- `python authoring/tools/g2_gate.py` مقدار/سبک/merged-range و شناسه‌ها را با رسمی مقایسه می‌کند؛ SHA نامزد را می‌سنجد؛ ۲۸ آزمون fixture رسمی را اجرا می‌کند؛ مبدل واقعی را در دایرکتوری موقت اجرا و JSON آزمایشی را validate می‌کند؛ پوشش سؤال هر فصل، وضعیت زرد و بدهی‌ها را گزارش می‌کند. JSON/PDF به مخزن یا موتور محصول نمی‌رود.
- شکست آزمون فنی = exit غیرصفر و اجازه ندادن به برچسب «قابل انتشار». پاسِ فنی = فقط «تکنیکی پاس؛ آموزشی باز»، نه سبز. اجرا در CI و محلی تکرارپذیر است؛ هیچ رمز یا دسترسی مدیر از کاربر نمی‌خواهد.

## کارهای بعدی که به‌طور کامل خودکار شدنی نیست

1. شاهد تصویری/کتاب کاغذی هر صفحه و خطاهای استخراج PDF باید در بسته‌های کوچک با بازرس دوم مقابله شوند. متن قابل استخراج، مخصوصاً نمودار و قطعات/ساعت، کافی نیست. عامل می‌تواند این بسته‌ها و آزمون‌های عددی را آماده کند و خطاها را اصلاح کند، ولی نباید رأی بازرس مستقل را از خودش بسازد.
2. سؤالِ مناسبِ موتور برای فصل‌های ۶–۸ نیازمند قرارداد اجراییِ جمع/تفریق، کسر/احتمال و آمار است؛ موتور کنونی ضرب‌محور است. صفحهٔ خارج از موتور را نباید با distractor تصادفی «پوشش» داد. تصمیم دربارهٔ خطای شناختی از روی گزینهٔ اشتباه به‌تنهایی قطعی نیست.
3. فقط پس از شاهد، ممیزی دوم و حکم معلم روی ردیف/سؤال مشخص، عامل می‌تواند با ثبت منشأ همان مورد را برای مُهر پیشنهاد کند؛ اجازهٔ انتشار نهایی مجزا است.

## دستور عملی تا فعال شدن check از راه دور

```bash
git fetch origin refs/heads/v10.3-beta:refs/remotes/origin/v10.3-beta
python -m pip install openpyxl==3.1.5
python authoring/tools/g2_gate.py --report authoring/G2-GATE-LATEST.fa.md
```

گیت محلی برای مبدل xlsx به Node/npm و دسترسی رجیستری نیاز دارد؛ همهٔ اجراهای آن در دایرکتوری موقت‌اند. آشتی تاریخچهٔ نامرتبط PR #3 و رسمی، ثبت workflow و دریافت اولین نتیجهٔ واقعی GitHub Actions یک **گیت فنی باز** است، نه وظیفهٔ معلم. ادغام با `--allow-unrelated-histories` بدون تحلیل تفاضل و محافظت از رسمی خطرناک است؛ نه مُهر و نه انتشار با دورزدن PR انجام شود. عامل باید راه ادغام امن را مستند کند یا محدودیت مجوز/پلتفرم را صریح گزارش دهد.

## «پیوسته» در این محیط به چه معناست؟

این گفت‌وگو یک فرایند دائمی ندارد: وقتی پاسخ عامل تمام شود، Agent Mode خودبه‌خود نوبت بعدی را اجرا نمی‌کند. CI می‌تواند با push/PR **آزمون مکانیکی** را به‌طور مداوم انجام دهد، اما خودش محتوای تازه نمی‌نویسد، PDF خصوصی Drive را نمی‌بیند و مُهر آموزشی نمی‌زند. برای تألیف واقعاً بی‌وقفه حتی بدون پیام جدید، یک **worker پایدارِ زمان‌بندی‌شده و مجاز** با دسترسی کنترل‌شده به منبع کتاب، صف کار، ثبت گزارش و بازرس مستقل لازم است؛ این زیرساخت در این چت در اختیار عامل نیست. هیچ credential را در گفتگو ندهید. تا وقتی آن زیرساخت نیست، هر نوبت فعال را با گیت/گزارش/گام بعدی مشخص ادامه می‌دهیم، نه ادعای اجرای پنهان بعد از پایان نوبت.

**اقدام فوری از کاربر:** هیچ برای گیت مکانیکی. تنها اگر قرار است معیار قدیمیِ «مُهر فقط با حکم صفحه‌ای معلم» تغییر کند، باید سیاست جدید را صریح و جداگانه تصویب کند؛ حتی آن صورت هم شاهد واقعی و ممیزی مستقل حذف نمی‌شود.
