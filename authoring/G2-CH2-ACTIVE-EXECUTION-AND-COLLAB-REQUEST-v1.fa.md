## نتیجهٔ همین مرحله

- فصل دوم چاپی ۱۹–۳۶: **۱۸ صفحه** به ردیف مشخص؛ پاکت مالک **۶۰–۹۰** در **۵ ردیف بودجه**، سه سطح **دانشی ۱۸–۲۷، کاربردی ۳۰–۴۵، استدلالی ۱۲–۱۸**. نقشهٔ مالک **۷ مبحث اصلی + ۲ فرعی** را با صفحه‌های اعلام‌شده به همان ردیف‌ها می‌افزاید؛ بودجه و نقشه یک‌به‌یک نیستند. برای هر صفحه UID نامزد، Qهای فعلی، اشارهٔ عنوان مبحث، خلأ شاهد آشیل/هدف راهنما/گونهٔ تمرین و وضعیت پذیرش جدا ثبت شد.
- موجودی تاریخی: **۲۸ Q نامزد زرد در ۷ صفحه**، **۱۱ صفحه بدون Q**؛ این اعداد از metadata نامزد می‌آیند، نه اسکن تازهٔ کتاب. `accepted_q_total=0`. تنها دو هم‌نامی لفظیِ «جمع و تفریق ده‌تایی» و «تقریب حاصل» به‌عنوان `LEXICAL_HINT_NOT_REVIEWED` آمده‌اند؛ بقیه ۹ مبحث `UNMAPPED` می‌مانند تا شاهد/هدف برسد. صفحه‌های ۱۹ و ۳۳ در spanهای صریحِ topic-map عنوانی ندارند؛ ص۳۳ Q نامزد دارد. این علامت **نیاز به تعیین نقش صفحه** است، نه ادعای خالی بودن آن.
- عدد ۶۰–۹۰ **پاکت برنامه‌ریزی سؤال‌های نهاییِ شاهددار** است؛ ۲۸ نامزد را با کسر خودکار از بودجه «قبول‌شده» فرض نمی‌کنیم. فوراً سهم هر ۵ ردیف و وضعیت‌های `UNKNOWN` در صف روشن شده‌اند تا بعد از snapshot آشیل/راهنمای معتبر، نگاشت شاهددار را بدون بازچینی از صفر پر کنیم. شاخهٔ مکمل ف۶–ف۸ با صفر Q و ف۳/ف۵ کم‌پوشش مطابق backlog قبلی ادامه دارد.

## پیگیری دو مدل همکار — متن کوتاه قابل ارسال، بدون توقف کار مستقل

**به آشیل / بخش ۱:**
> برای پایلوت فصل ۲ ریاضی دوم C205، لطفاً مشخص کن آیا snapshot اکسل استانداردِ استخراج و انطباق‌یافتهٔ چاپی ۱۹–۳۶، دفتر شاهد صفحه/Q و metadata چاپ/منبع را در GitHub commit کرده‌ای؟ اگر بله `ref + commit SHA کامل + path + SHA-256 بایت + receipt/path + دامنهٔ تأیید استخراج` را بده؛ نقش چاپی صفحات ۱۹ و ۳۳ را هم با ارجاع شاهد روشن کن (۳۳ اکنون Q نامزد دارد ولی در span نقشهٔ مبحث قرار نگرفته). اگر هنوز نرسیده، زمان وعده نده؛ اولین دامنهٔ کوچک آماده و مانع مشخص را اعلام کن. انطباق اکسل با کتاب بر عهدهٔ توست؛ فایل‌ها/عکس دارای حق نشر و مُهر تازه را بدون مجوز وارد Git نکن. من meanwhile صف و آزمون‌های فصل ۲ را پیش می‌برم.

**به Z.ai / بخش ۳:**
> برای مصرفِ خروجی ممیزی آرنا، لطفاً یک پاسخ نسخه‌دارِ محدود بده: آیا manifest پین‌شده به `producer_commit+workbook_sha+assessment_commit+manifest_sha+UID+decision_ref` را در dry-run می‌خوانی، و چه schema/engine version/contract و مکانیک‌های سؤال، بازخورد و گزارش معلم را می‌پذیری؟ یک تست ردِ SHA یا decision_ref نامنطبق و مسیر GitHubِ `consumer_receipt` را مشخص کن. پیش از پذیرش انسانی UIDهای ارزیابی‌شده فقط synthetic/dry-run، نه runtime/انتشار. API را یک‌جانبه عوض نکن؛ نبود قرارداد را با blocker و فیلدهای لازم پاسخ بده.

**آرنا تا دریافت پاسخ‌ها:** بهینه‌سازی صف و گیت مستقل concept/score/coverage، کنترل انتشار redacted و تست fail-closed را ادامه می‌دهد؛ پاسخ دیگری از مالک برای این گام‌ها لازم نیست. وقتی بستهٔ واقعی برسد، تطبیق بایت/چاپ/هدف و تست ابطال روی همان SHA اجرا خواهد شد. درخواست‌های بالا برای جلو انداختن اتصال طرفین است، نه انتقال کار اسکن یا کنترل انبوه Q به مالک.
