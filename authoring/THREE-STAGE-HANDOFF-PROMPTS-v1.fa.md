# پیام‌های تحویل برای آشیل (بخش ۱) و Z.ai (بخش ۳)

**۲۰۲۶-۱۰-۲۴ | قابل ارسال توسط مالک؛ متن هماهنگی است، نه ادعای ارسال/پذیرش یا تأیید محتوایی.** نقشهٔ حاکم: منبع دقیق کتاب و راهنمای معلم → ثبت منبع/چاپ/حقوق/hash در GitHub → استخراج صفحه‌به‌صفحه و دفتر شاهد و snapshot اکسل آشیل → ممیزی و ثبت ارزیابی آرنا در GitHub → پذیرش *محدوده‌دار* انسان/مالک → بستهٔ تمرین/بازی و ابزار معلم در Z.ai → آزمون و انتشار مجاز. توضیح قرارداد پیشنهادی در [GITHUB-THREE-STAGE-CONTENT-FLOW-v1.fa.md](GITHUB-THREE-STAGE-CONTENT-FLOW-v1.fa.md). این دو پیام را می‌توان بدون تغییر برای عوامل فرستاد. پاسخ‌های آنان باید در مسیر نسخه‌دار مخزن یا PR واقعی باشد؛ گفت‌وگوی سه عامل، استقرار ربات یا ACK خودکار فرض نمی‌شود.

## پیام آماده برای بخش ۱ / آشیل

> منبع G2 اولویت پایلوت است. مسئولیت اسکن و تأیید انطباق اکسل با کتاب/چاپ با شماست؛ آرنا اکسل استاندارد هفت‌شیتی را ورودی کتاب فرض می‌کند، ولی بایت/شناسه/رسید را خودش کنترل خواهد کرد. لطفاً بدون تغییر قالب استاندارد فعلی، برای **یک تحویل کوچک و قابل بازپخش** از فصل/دامنهٔ واقعاً ممیزی‌شده، این خروجی‌ها را روی شاخه/PR خود در مخزن خصوصی برنامه فراهم کنید؛ دامنهٔ استخراج را به کل G2 تعمیم ندهید.
>
> ۱. برای کتاب و راهنمای معلم: شناسه/چاپ/سال/منبع، SHA-256 هر بایت اصلی در دسترس، وضعیت دسترسی و **مرجع تصمیم مستقل دربارهٔ اجازهٔ دریافت و نگهداری بایت XLSX در همین GitHub خصوصی** را در `authoring/content-exchange/source-registry/G2/C205/<edition-id>/source-manifest.json` (یا با پیشنهاد مسیر سازگار) ثبت کنید؛ در صورت نبود هش/اجازه، `UNKNOWN` بنویسید. PDF/اسکن/crop/تصویرِ حق‌نشری، متن کامل راهنما و secret را در Git قرار ندهید؛ خصوصی‌بودن مخزن مجوز نیست. اگر حق XLSX احراز نشده، بایت را منتقل نکنید و `BLOCKED_FOR_GITHUB_RAW_BYTES` بزنید. SHA راهنمای نسخهٔ دیگر بدون crosswalk مرورشده، هدف قطعی این چاپ نیست.
>
> ۲. استخراج صفحه‌به‌صفحه + دفتر شاهد redacted را با ارجاع چاپی/PDF و status هر صفحه/سؤال (`VERIFIED | UNKNOWN_REVIEW | CONFLICT`) تهیه کنید؛ موارد ناخوانا را حدس نزنید. snapshot اکسل همان هفت شیت/سرستون/UID و Q→L برنامه باشد؛ fixture، draft و snapshot واقعی جدا بمانند. برای هر مورد فقط دامنهٔ واقعاً تطبیق‌شده را اعلام کنید، نه تأیید کل صفحه از حکم محدود. اصلاحات کاربر دربارهٔ ص۷/چاپی۱، چاپی۴، ۱۱ و ۱۵ را به‌عنوان رأی مالک از اسکن مستقل جدا ثبت کنید؛ چاپی۱۵ «عدد بعد از ۲۴» است، نه ۲۸.
>
> ۳. در صورت مجوز حقوقی: snapshot و رسید را در مسیر پیشنهادی `authoring/content-exchange/incoming/G2/C205/<edition-id>/<sha256>/extraction-snapshot.xlsx` و `extraction-receipt.json` commit کنید. رسید هم-commit مطابق قرارداد آزمایشی `achilles-extraction-bundle/v1` شامل `producer=ACHILLES`, `approval_status=EXTRACTION_VERIFIED`, `book_id`, `edition_id`, `book_source_sha256`, `workbook_sha256`, `repo_path`, `extraction_scope`, `verified_by`, `decision_ref`, `evidence_manifest_sha`, `storage_rights_status=REVIEWED_FOR_PRIVATE_REPO`, `rights_decision_ref`, `receipt_id` باشد. `git_commit` را **داخل رسید هم-commit** نگذارید (خودارجاعی هش). پس از commit، **SHA کامل commit + ref + path + SHA-256 فایل + path رسید و دفتر شاهد/دامنه** را در پیام PR یا handoff جدا اعلام کنید. عنوان `EXTRACTION_VERIFIED` فقط صحت استخراج در محدودهٔ اعلام‌شده است، **نه پذیرش آموزشی صاحب‌اختیار**.
>
> ۴. اگر این نام مسیر/schema برای کار جاری شما ناسازگار است، به‌جای تغییر خودکار API/اکسل، یک جدول تطبیق دقیق فیلدها، وضعیت‌ها و مانع واقعی بدهید تا adapter آرنا آگاهانه بازنگری شود. درخواست تأیید دسته‌جمعیِ سؤال‌ها یا لینک تازهٔ PDF از مالک نکنید؛ فقط اختلاف موردیِ مستند را ارجاع دهید. تأیید کلی نقشه یا سکوت مالک حکم آموزشی نیست.

**توقع پاسخ قابل کنترل:** PR/commit + فهرست دقیق مسیر/هش/دامنه/چاپ/مرجع حق ذخیره؛ یا `BLOCKED` با دلیل و حداقل اقدام لازم. آرنا فقط پس از روشن شدن حق دریافت، از commit پین‌شده fetch می‌کند. رسید ادعایی به‌تنهایی احراز حقوق یا هویت تأییدکننده نیست.

## پیام آماده برای بخش ۳ / Z.ai

> معماری/هسته و API را بدون قرارداد مشترک تغییر ندهید. نقشهٔ مالک این است: ابتدا آشیل استخراجِ منبع/چاپ/حقوق و snapshot را در GitHub ثبت می‌کند؛ سپس آرنا اهداف راهنمای معتبر را با دامنهٔ چاپ تطبیق داده و assessment نسخه‌دار را در GitHub می‌گذارد؛ **بعد از آن** صاحب‌اختیار، فقط UID/دامنهٔ روشن را می‌پذیرد؛ بخش ۳ بستهٔ بازی/تمرین و ابزار معلم را می‌سازد و آزمون می‌کند. تصویب کلی طرح قبلی یا وضعیت `PROPOSED_YELLOW` مجوز مصرف runtime یا انتشار نیست.
>
> ۱. لطفاً **بدون انتظار برای آماده شدن محتوای واقعی**، قرارداد پیشنهادیِ read-only مصرف را بازبینی و پاسخ نسخه‌دار بدهید: آدرس/قالب manifest آرنا؛ `assessment_commit` کامل و manifest SHA؛ `producer_commit` و `workbook_sha256`؛ UID و چاپ/guide/profile SHA؛ schema/mapping قابل پذیرش، حد مجازِ متن/تصویر در runtime، نسخهٔ موتور و converter، قابلیت‌های مکانیک، فارسی/RTL، کلید/بازخورد و دادهٔ موردنیاز ابزار معلم. raw workbook به‌تنهایی محتوای پذیرفته‌شده نیست؛ اگر قرارداد/فیلد دیگری لازم است، migration/آزمون سازگاری پیشنهاد دهید نه تغییر یک‌جانبه.
>
> ۲. گیت جداگانه بگذارید: **پیش از پذیرش انسانی محدوده‌دار** فقط dry-run و آزمون ساختگی/بدون نشر؛ برای ورود UID به بستهٔ واقعی، مرجع تصمیم معتبر با scope، `assessment_commit` و SHA یکسان الزامی باشد؛ `UNKNOWN_REVIEW`, `BLOCK_CRITICAL_SCOPE_DRIFT`, حق نامعلوم، schema mismatch یا status زرد ⇒ HOLD/BLOCK. گیت دیگری هم برای انتشار پس از آزمون موتور/حقوق/تأیید مجاز لازم است؛ تصمیم آموزشی ≠ مجوز نشر.
>
> ۳. برای پایلوت، خروجی پیشنهادیِ بازی/تمرین **و ابزار معلم** را با UID→هدف→گونهٔ تمرین→بازنمایی/CPA→بازخورد/خطای مفهومی→گزارش معلم طراحی کنید. معیار وسعت تمام کتاب + عمق گونه‌های هر مبحث را در قرارداد coverage نگه دارید؛ یک نمونهٔ خوش‌نما جای پوشش نیست. نگاشت هدف و score و تکرار را اختراع نکنید؛ unknown و مقدار null را به صفر/سبز تبدیل نکنید. وضعیت capability را به `SUPPORTED[_WITH_LIMITS] | NEEDS_IMPLEMENTATION | NOT_SUPPORTED` تفکیک کنید.
>
> ۴. نتیجهٔ قرارداد/آزمون را در PR/مسیر نسخه‌دار GitHub به‌صورت `consumer_receipt` بدهید: ref/commit و SHA ورودی آرنا، decision_ref و دامنهٔ انسانی (یا نبود آن در dry-run)، engine/converter/schema version، UIDهای تست‌شده، نتیجهٔ correctness/boundary/RTL/feedback/teacher-tool، PASS/BLOCKED و علت. نتیجهٔ مصنوعی را صریحاً `SYNTHETIC_ONLY` بنامید؛ متن چت به‌جای receipt نسخه‌دار نیست. branch یا سر رسمی را خودکار merge نکنید.
>
> ۵. پاسخ اولیهٔ مطلوب: فهرست فیلدهای مورد نیاز، قابلیت‌ها/شکاف‌ها، طرح رسید مصرف و یک آزمون منفی از mismatch SHA یا decision_ref؛ اجرای بازی/انتشار تنها پس از بستهٔ تأییدشده و مجوزهای واقعی. اگر منبع/قرارداد هنوز نرسیده، کار مستقل را ادامه دهید و وضعیت blocker را دقیق بنویسید؛ آرنا نیز منتظر شما برای ممیزی محتوای مجاز نمی‌ماند.

**توقع پاسخ قابل کنترل:** قرارداد/manifest قابلیت یا PR نسخه‌دار + آزمون synthetic و blockerهای صریح؛ نه ادعای استقرار یا قبولی محتوا. درخواست تولید انبوه یا تأیید ردیف‌به‌ردیف از مالک مطرح نشود؛ موارد خاص با شاهد و UID برای تصمیم او آماده شوند.

## وضعیت همین پیام‌ها

ارسال این دو متن به عوامل توسط مالک **اختیاری اما مفید برای هماهنگی قرارداد** است. تا زمانی که خود عامل‌ها به‌طور قابل بررسی پاسخ نداده‌اند، هیچ تبادل زنده/ACK پذیرفته‌شده‌ای ادعا نمی‌شود. آرنا همزمان کار مستقل خود روی گیت GitHub، ممیزی مفهوم و آماده‌سازی sidecar را پیش می‌برد؛ گیت انسانی پس از ممیزی و قبل از محتوای قابل مصرف بخش ۳ است، نه گیت دریافت خام آشیل.
